# AI Architecture Audit — bootstrap-claude — 2026-09-13

**Architecture shape:** Multi-agent, hierarchical orchestrator-worker, 3 levels deep (`power-mode` → `tackle` agent → implementation subagents). No LLM SDK or agent framework — the orchestrator is a markdown skill definition running on the Claude Code harness (`package.json:1-33` declares zero runtime dependencies). Roles: orchestrator, task-creator, tackler, UAT-generator, UAT-judge.
**Categories audited:** all 9.

## cost-resource-controls — Cost & Resource Controls

| Check | Status | Notes |
|-------|--------|-------|
| CR1 | ❌ | **The orchestrator loop is unbounded.** "Run until `/roadmap-next` reports no items remaining" (`power-mode/SKILL.md:127`), "Immediately return to Step 1. No pausing, no reporting, no confirmation" (`:183`), with stopping-to-ask explicitly forbidden (`:120-123`). No max-wave counter, no budget check, no circuit breaker — and Step 2 *materializes new task files* (`:133-145`), so the loop can add work to its own queue |
| CR2 | ❌ | No token or cost budget at any level |
| CR3 | ❌ | Bounded below, not above. "Spawn all agents in the safe group simultaneously" (`power-mode/SKILL.md:39`) has no ceiling — a 30-item wave spawns 30 concurrent agents, each of which may spawn up to 3 more via `tackle` (`tackle/SKILL.md:94`). The caps exist in `now` and `tackle` but not in the one skill that needs them most |
| CR4 | ❌ | No cost-anomaly alerting (`README.md:425`) |
| CR5 | ⚠️ | No automatic per-agent timeout, but a hung-agent policy exists: terminate and mark `[BLOCKED]` (`tackle/SKILL.md:121`), with mandatory process termination (`tackle/SKILL.md:94`, `now/SKILL.md:36`) — detection is human, not automatic |

**Category verdict**: FAIL (2 HIGH failures, CR1 and CR3)
**Priority mitigations**: highest-value finding of this audit. Unbounded loop + unbounded fan-out + mandated `bypassPermissions` + zero cost visibility all live in the same skill, and each one removes a brake the others would have relied on. A max-concurrent ceiling in the Parallelization Mandate and a max-wave counter in the orchestrator loop are both small, local edits.

## safety-composition — Cross-Agent Safety Composition

| Check | Status | Notes |
|-------|--------|-------|
| SC1 | ⚠️ | No system-level behavioral test. All 23 files in `test/` cover installers, settings merges, and file layout (`install-global.test.js`, `settings-hooks.test.js`, …); UAT verifies per-task outcomes, not emergent wave behavior. | SC2 | ⚠️ | Every spawned agent is mandated to `mode: "bypassPermissions"` (`power-mode/SKILL.md:46`) — including Phase 2 UAT-generation, described as read-only (`:160`). | SC3 | ✅ | Uniform scoping by construction — same footer, same globally-installed hooks for every agent; no agent receives a different grant |
| SC4 | ❌ | No aggregate behavioral monitoring; a subagent that over-triggers a tool is invisible. Downstream of the observability gap |
| SC5 | ⚠️ | Split enforcement: the Serena mandate is code-level and hard-blocking (`serena-edit-guard.js`, `serena-write-guard.js`), but the *orchestration* boundaries — max 3 sub-processes, min 5 agents, "no re-planning" — are prompt-level only, with no hook behind them. **Category verdict**: WARN (CRITICAL check SC2 is mitigated, not failed; 1 MEDIUM failure)
**Priority mitigations**: drop `bypassPermissions` from Phase 2, which is read-only and doesn't need it — a one-line reduction of the largest bypass surface the repo has already inventoried at `permission-mode-control-survival.md:50`.

**Overall architecture posture: HIGH** — no CRITICAL check fails outright (the peer-topology check OT3 passes cleanly, and SC2's bypass surface is mitigated by deny rules that survive bypass), but six HIGH checks fail: OT2, OB1–OB3, CR1, CR3.

The shape of the result: the *design* is right and the *state management* is excellent — hierarchical orchestration, deterministic routing, disk-durable state, fail-closed verification. The gaps are all in the operational envelope around it: nothing bounds the loop, nothing bounds the fan-out, and nothing observes either.

**Top 3 actions to take now:**
1. **Bound `power-mode`** (CR1, CR3) — add a max-concurrent-agent ceiling to the Parallelization Mandate (`power-mode/SKILL.md:27-41`) and a max-wave counter to the orchestrator loop (`:125-183`). Smallest edit, largest risk reduction.
2. **Fix parallel-closure contention** (OT2) — serialize `UAT-CORE.md:146-159` closure writes, or extend the collision check to cover shared index/roadmap/git-index writes. Not currently tracked by any bug.
3. **Close the observability gap** (OB1–OB3, OB5) — the task line is already drafted at `raw/research/ai-agent-architecture-observability/index.md:112`, and a `/decision-create` for the backend default at `:114`.
