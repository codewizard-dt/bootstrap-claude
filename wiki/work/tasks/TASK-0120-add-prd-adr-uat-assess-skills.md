# TASK-0120 — Add prd-assess, adr-assess, and uat-assess skills mirroring roadmap-assess/bug-assess

relates_to::[[wiki-skill-boilerplate-duplication]]

## Objective

Give every `wiki/work/` family a common `assess` action (ROADMAP-0014 Phase 4, item "Add `prd-assess`, `adr-assess`, and `uat-assess`"). Add three **new, strictly read-only** skills — `lib/skills/prd-assess/`, `lib/skills/adr-assess/`, `lib/skills/uat-assess/` — each mirroring `lib/skills/roadmap-assess/SKILL.md` and `lib/skills/bug-assess/SKILL.md`: survey every active item in the family, rank them by family-specific signals, and print a terse per-item status update with a suggested next command. Register each skill in `lib/skills/README.md`, the `CLAUDE.md` Custom Commands table, and the Serena skill-category memory, and pin each with a per-skill contract test. Nothing is implemented here beyond the three skills, their registration rows, and the test — no other skill is changed, and nothing under `~/.claude/` is touched.

Binding inputs: the Q&A decisions of 2026-09-19 (items 1-8) and the Phase 4 sequencing note in [ROADMAP-0014](../roadmaps/ROADMAP-0014-wiki-skill-deduplication-fixes.md) Notes — in particular item 5 (roadmaps/decisions/requirements stop using `archive/`; UAT keeps it) and item 7 (the three assess skills mirror `roadmap-assess`/`bug-assess`).

## Approach

**Sequencing.** This task follows TASK-0119 (last of the Phase 4 skill renames, so the `prd-*`/`adr-*` names, the family ID prefixes, and the status vocabulary already exist when this runs) and precedes TASK-0121 (the `archive/` removal for roadmaps, decisions and requirements). The renames and the archive removal touch `lib/skills/README.md`, `CLAUDE.md`, and `.serena/memories/skills/format-and-model-selection.md` — the same files this task adds rows to — so every edit to those three is a minimal, anchored exact-string edit made after a fresh `Read` (concurrent tasks edit sibling lines). Never rewrite them whole.

**Source-of-truth note.** Edit `lib/skills/`, never `~/.claude/skills/`. Do not run `install-global.sh` (TASK-0122 owns the installer prune; new skills reach the installed copy via the next normal install).

**Mirror, do not restate.** The three skills share the `roadmap-assess`/`bug-assess` skeleton — Step 1 Discover, Step 2 Parse, a cross-item analysis step, a Rank step with an explicit precedence list, a Report step with numbered sub-blocks (6a…), and a `## Constraints` block — and take the shared mechanics from `lib/skills/_shared/`:

- **`SKILL-BOILERPLATE.md`**: open with the inline Prereqs line in the verbatim grammar — `**Prereqs:** obey \`wiki/guides/mcp-tools.md\`; run /primer if not done this session.` (all three explore the wiki, so the `/primer` clause is right; do **not** add a `+ lifecycle.md` reference for `requirements`/`decisions` — the grammar in `test/skill-boilerplate.test.js` only allows `tasks|bugs|uat`; `uat-assess` may add ` + \`wiki/work/uat/lifecycle.md\``). No Edit hygiene or Number allocation section is needed — the skills never write, so they neither allocate nor edit. Do not restate any of the boilerplate.
- **`ID-RESOLUTION.md`**: the **Family table** is the only place a family's directory and ID prefix live — read it at run time instead of hardcoding the prefix. Where a skill must follow a cross-family reference to one file (`uat-assess` following a UAT's `task:` back-link), use the wiring line, not a re-described lookup: `Resolve the file per ~/.claude/skills/_shared/ID-RESOLUTION.md — family: tasks · scope: active+archive · ambiguous: headless · empty: n/a` (headless because these skills never prompt; the task may already be archived when its UAT is still active). Add one matching row for `uat-assess` to that doc's **Caller deltas** table.
- **`roadmap-next`'s Parse-a-roadmap procedure**: `adr-assess` and `uat-assess` need each linked roadmap's checklist state; reference the procedure by name exactly as `roadmap-assess` Step 2 does — never restate it.

**Frontmatter (all three)** — copy `roadmap-assess`'s tier verbatim; it is `category: researching` and `model: claude-sonnet-5`, `disable-model-invocation: false`, `user-invocable: true`. Re-read `roadmap-assess/SKILL.md`'s frontmatter at implementation time and match whatever it says then (the contract test reads it from the file rather than hardcoding). No `argument-hint` (these skills take no arguments — like `roadmap-assess`/`bug-assess`). `description:` starts "Survey all active …".

**Read-only, stricter than the models.** `roadmap-assess` auto-archives complete roadmaps and `bug-assess` batch-triages open bugs; **the new skills have no write exception at all**. Permitted tools: `list_dir`, `find_file`, `search_for_pattern`, `Read` — no `Edit`, `Write`, `Bash`, or `AskUserQuestion`, no log entry, no index edit. They never run a UAT's `Unit Test Command`, never flip a status, never create a file. Ambiguity is reported, not asked. Keep the report terse — no preamble, no closing summary beyond the tables.

**Status-not-directory reading (PRD/ADR).** After TASK-0121, terminal roadmaps, decisions and requirements stay in their family directory and are distinguished only by `status:` (and a Closed section in the family `index.md`). Until then, terminal files may still sit in `archive/`. So `prd-assess` and `adr-assess` must: `list_dir` the family directory for files directly in it, **read each file's status** to decide active vs. closed, and never treat directory location as the signal. They must not mention `archive/` for their own family at all (that removes them from TASK-0121's edit list). Terminal items are excluded from ranking and summarized in one footer line (`Closed: N (not assessed)`). `uat-assess` keeps `archive/` (tasks, UAT and bugs keep it): scan only files directly in `wiki/work/uat/`, skip `archive/` and `screenshots/`, and *also* read `status:` since a terminal UAT may not have been swept yet.

**Legacy IDs.** The `npx … update` migration that renames `REQ-`/`DEC-` files to `PRD-`/`ADR-` runs in a later task, so during this task's lifetime the family directories hold both prefixes. `prd-assess` matches `PRD-*.md` and `REQ-*.md`; `adr-assess` matches `ADR-*.md` and `DEC-*.md`; cross-references are searched under both prefixes (and by `aliases:`). Take the exact prefixes and status names (`retired` vs. a renamed terminal status, `deprecated`) from `ID-RESOLUTION.md` and the family `lifecycle.md` as they stand after TASK-0119 — re-read them; treat any status the lifecycle marks terminal as closed rather than hardcoding one word.

### Family-specific ranking signals

Each skill's Rank step states an explicit precedence list, exactly like `bug-assess` Step 5. Each item gets a one-sentence rationale that the report labels a judgment call. Named thresholds live once at the top of the Rank step so they are easy to tune.

**prd-assess** (family `wiki/work/requirements/`). Parse frontmatter (`id`, `title`, `status`, `owner`, `created`, `updated`, `tags`, `stakeholders`) and `## Amendment N` blocks. Derive, per PRD, the set of downstream items by `search_for_pattern` for its ID and aliases across `wiki/work/decisions/`, `wiki/work/tasks/`, and `wiki/work/roadmaps/` (frontmatter `linked_requirements`/`linked_prds`, typed links such as `derived_from::`/`implements::`, and plain `[[…]]` links). Precedence, highest first:
1. **Approved with no linked ADRs and no linked tasks** — approved but nothing downstream exists; oldest `updated` first.
2. **Approved and blocked by open decisions** — a linked ADR block is still `proposed` (resolve the block's `Status:`; follow a `superseded by` pointer to the successor per `roadmap-assess` Step 4 item 4, then re-check).
3. **Stale drafts** — `status: draft` with `updated` older than 30 days.
4. **Fresh drafts.**
5. **Approved and fully flowing** — every linked ADR block accepted and at least one task exists; needs nothing.
Tie-break: oldest `updated`, then ID ascending. `Next` by state: unlinked approved → `/adr-extract <file>` (or `/task-create` when the PRD needs no architectural decision); blocked → `/adr-finalize <adr-file>#DM`; draft → `/prd-finalize <file>` (stale draft: or `/prd-deprecate <file>` if abandoned); flowing → none needed, cite the linked task/roadmap. Empty family → STOP `No active PRDs found in wiki/work/requirements/. Use /prd-create <idea> to draft one.`

**adr-assess** (family `wiki/work/decisions/`). Status is **per decision block**, so the ranked unit is the block (`ADR-NNNN#DM`, listed under its group). Parse each group's frontmatter and every `## DM.` block's `Status`, `Date`, `Supersedes`, `Tags`, and `### Links` (`Source task(s):`). Also search active tasks for `implements::[[ADR-NNNN#DM]]` (and `DEC-` forms) so a task that exists but was never written into `### Links` still counts. **This skill folds in the `adr-next` check**: any accepted block with no task reference is surfaced here. It does not remove `adr-next` or `wiki-lint` check 2.12 — those stay as the fast single-purpose forms. Precedence, highest first:
1. **Proposed blocks that gate live work** — referenced by an active roadmap's decision-reference set or by a PRD/task; more gated items outranks fewer.
2. **Accepted blocks with no task** — decided but never scheduled; oldest `Date` first.
3. **Other proposed blocks** — oldest `Date` first (age = today − `Date`).
Supersession chains: follow every `Supersedes:` / `superseded by` pointer and render each chain (`ADR-0001#D2 → ADR-0004#D1`); warn on cycles, on a `superseded` block whose successor is not `accepted`, and on asymmetry (`Supersedes:` set on the new block but the old block not marked, or the reverse). A proposed block that would supersede an accepted one is annotated in its row. Fully accepted groups whose blocks all have tasks, and superseded blocks, are closed: excluded and counted in the footer. `Next`: proposed → `/adr-finalize <file>#DM` (a group with several proposed blocks: `/adr-walkthrough <file>`); accepted without a task → `/task-create <description> --decision ADR-NNNN#DM`; a long-idle proposed block: or `/adr-deprecate <file>#DM`. Empty family → STOP `No active ADRs found in wiki/work/decisions/. Use /adr-create <topic> to create one.`

**uat-assess** (family `wiki/work/uat/`). Parse frontmatter (`id`, `title`, `status`, `task`, `created`, `updated`) and every test case: the `### UAT-…` headings and each case's marker (`[ ]`, `[x]`, `[FAIL: …]`, `[SKIP: …]`). Classify each unresolved case as **unit-backed** (has a `Unit Test Command` line, or `Repeatable Unit Test: Created`) or **manual-only** (`Not applicable`/`Blocked`, or no command). A UAT with zero `### UAT-…` case headings, or only the skeleton left by `/uat-skip`, is a **stub**. Resolve each UAT's `task:` per the wiring line above, read that task's status and its `blocks:` array, and `search_for_pattern` for `[[TASK-NNNN` in `wiki/work/roadmaps/` to find the roadmap item the UAT's task would tick (read roadmap state through the `roadmap-next` Parse procedure; roadmaps are read by status, not directory). Precedence, highest first:
1. **Unblocking power** — the UAT's task `blocks:` other tasks (hard order: a UAT gating another task outranks the ones it gates) or is the last unchecked item of its roadmap.
2. **What it waits on**, in this order: `failed` (a `[FAIL: …]` case — needs a fix) → `in-progress` (partially walked) → `pending`, all unresolved cases unit-backed (runnable headless via `/uat-auto`) → `pending` with any manual-only case (needs a human) → stub.
3. **Age**, oldest `created` first, then `UAT-NNNN` ascending.
Report a **Waits on** column (`failing case`, `partial walk`, `auto-runnable`, `manual cases: N`, `stub`) and an **Unblocks** column (the gated `TASK-NNNN` IDs and/or `ROADMAP-NNNN` item). `Next`: failed → fix, then `/uat-auto <file>` (or `/bug-create` for a real defect); in-progress → `/uat-walk <file>`; auto-runnable → `/uat-auto <file>`; manual-only → `/uat-walk <file>`; stub → `/uat-create TASK-NNNN` to regenerate, or `/uat-skip <file>`. Warnings: UAT whose task is missing or terminal (`/task-close` candidate), status/marker drift (e.g. `passed` with unchecked cases, `pending` with checked cases), and rows missing or stale in `wiki/work/uat/index.md`. Empty family → STOP `No active UATs found in wiki/work/uat/. Use /uat-create <task> to generate one.`

**Report shape (all three).** In order: `6a` Prioritized table (Rank · item · status · signal columns above · rationale · blocks/blocked-by), `6b` per-item status block in ranked order (`### <ID> — <title>`, owner/assignee if any, status, one-line summary, `Next:`), `6c` Warnings (omit if none), footer `Closed: N (not assessed)` when terminal items were skipped. Mirror `roadmap-assess`'s output style but number the sub-blocks consistently (do not copy its 6a-under-Step-7 label mismatch).
