# TASK-0111 — Rename task-trash to task-close

depends_on::[[TASK-0110]]
blocks::[[TASK-0112]]

## Objective

Hard-rename the `task-trash` skill to `task-close` (ROADMAP-0014 Phase 4, Family & Action Vocabulary Standardization) so every `wiki/work/` family shares a common `close`/`create`/`assess` action vocabulary. Move `lib/skills/task-trash/` to `lib/skills/task-close/`, update its `name:` frontmatter, description and self-references, and sweep every live reference to the old name. **The skill's behavior is unchanged by this rename — only the name changes.** It still flips `status: trashed` on the task and its matching UAT files, still archives them via `ARCHIVE-WORK-ITEM.md` (`family: tasks` then `family: uat`), still logs with op `task-trashed`, and still leaves roadmap/decision references intact. No redirect stub is left behind.

## Approach

Decisions were made in the ROADMAP-0014 Phase 4 Q&A on 2026-09-19 (recorded in that roadmap's Notes, item 4: old skill names are hard-renamed with no redirect stubs; the installer prunes stale installed copies). This task only executes the `task-trash` item.

- **Rename mechanics.** `git mv lib/skills/task-trash lib/skills/task-close` when the directory is tracked (check with `git ls-files lib/skills/task-trash`); plain `mv` if untracked. The directory holds only `SKILL.md`.
- **Behavioral identifiers stay.** `status: trashed`, the `task-trashed` log op, and `terminal_status: trashed` are status/op vocabulary, not the skill name — they do not change. Existing `wiki/log.md` entries with `task-trashed` remain valid. The tests already pin `task-trashed`; keep those assertions.
- **Sweep scope (live references).** `lib/skills/**` (incl. `_shared/`), `lib/scripts/**` (incl. `templates/`), `lib/hooks/**`, `lib/prompts/**`, `test/**`, `README.md`, `CLAUDE.md`, `lib/skills/README.md`, `.serena/memories/**`, and non-historical `wiki/` pages. The pre-implementation sweep (`task-trash` across the repo) found live hits in: `lib/skills/task-trash/SKILL.md`, `lib/skills/_shared/ID-RESOLUTION.md` (family table row), `lib/skills/_shared/ARCHIVE-WORK-ITEM.md` (caller-deltas row), `lib/skills/wiki-tidy/SKILL.md`, `lib/skills/req-retire/SKILL.md` (2 example lines), `lib/skills/README.md`, `CLAUDE.md` (Custom Commands table), `lib/scripts/templates/wiki/work/tasks/lifecycle.md`, `lib/scripts/templates/wiki/work/uat/lifecycle.md`, `wiki/work/tasks/lifecycle.md`, `wiki/work/uat/lifecycle.md`, `wiki/knowledge/concepts/wiki-skill-boilerplate-duplication.md`, `.serena/memories/project/overview.md`, `.serena/memories/skills/format-and-model-selection.md`, `test/archive-work-item.test.js`, `test/shared-id-resolution.test.js`, and a comment in `test/skill-boilerplate.test.js`. `README.md` and `lib/scripts/templates/CLAUDE-wiki.md` had no hits at sweep time — re-check them anyway; another task in this chain may have added references.
- **Historical records are left alone.** `wiki/log.md` (append-only), `raw/` (immutable), `wiki/hot.md` (regenerated by the lead, not this task), every `archive/` directory, `wiki/knowledge/sources/` (frozen source summaries), `wiki/work/roadmaps/` (ROADMAP-0014 itself names the old skill as the rename subject), and individual `TASK-*.md` / `UAT-*.md` work-item files plus `wiki/work/tasks/index.md` (frozen specs and catalog titles that must be able to name the old skill — including this file). Two pending UAT files (`UAT-0088`, `UAT-0091`) contain a "clean up with `/task-trash`" hint; they are frozen records and may be under a concurrent `/uat-auto` run, so leave them and read that hint as `/task-close`.
- **Not touched.** `~/.claude/skills/task-trash` (the installed copy) and `install-global.sh` are out of scope; do not run the installer. TASK-0122 makes `install-global.sh` prune stale installed skill dirs.
- **Description wording.** The frontmatter `description:` currently starts "Trash a task and its related UAT files — moves them to archive/ ...". Reword it around "Close" while keeping the semantics visible, e.g. "Close out an abandoned task and its related UAT files — sets status trashed, moves them to archive/, and removes all active-index references". The H1 `# Trash Task` becomes `# Close Task`; the body's `status: trashed` / `terminal_status: trashed` / `task-trashed` wording stays.
- **Residue test.** A new hermetic test asserts no live `task-trash` reference remains, using an explicit exclusion list mirroring the "historical records" rules above, so future work cannot silently reintroduce the old name.
