# TASK-0117 — Rename the decisions family's skills to ADR and make ADR- the new-item prefix

relates_to::[[wiki-skill-boilerplate-duplication]]
relates_to::[[skill-family-rename-pattern]]

## Objective

Hard-rename the `decisions` family's four skills so the family adopts the **ADR** label ROADMAP-0014 Phase 4 standardizes on: `decision-create` → `adr-create`, `decision-finalize` → `adr-finalize`, `decision-walkthrough` → `adr-walkthrough`, `decision-next` → `adr-next`. New Decision Group files are created with an `ADR-NNNN` ID and an `ADR-NNNN-slug.md` filename (4 digits); the per-decision anchor becomes `ADR-NNNN#DM`. The `wiki/work/decisions/` directory name is **kept**. Existing `DEC-` items (today only `DEC-0001`) are **not** renamed here — the `npx … update` migration (a later ROADMAP-0014 Phase 4 task) renames them and keeps the old ID in `aliases:`, so until then `DEC-` references must keep resolving. Roadmap item: ROADMAP-0014 Phase 4 ("Rename the `decisions` family's skills to **ADR**"); binding decisions are items 1-4 of that roadmap's 2026-09-19 Q&A notes (ID prefixes, directories keep names, hard rename with no redirect stubs) plus its sequencing note.

`adr-next`'s check is also folded into `wiki-lint` (check 2.12, TASK-0093) — that behavior is unchanged; only names and ID forms move.

## Approach

**Sequencing**: runs after TASK-0116 (the `prd-*` family rename, the previous link in the Phase 4 chain — use the `prd-*` skill names it produced, including in the PRD-side skill that references `/decision-create`) and before TASK-0118 (`req-extract-decisions` → `adr-extract`, a **separate** task; do not rename that skill here). Earlier chain tasks already renamed `task-create`, `task-close`, `task-assess`, `uat-create`, `bug-create` — use those names. Many neighbouring tasks touch the same files, so every edit is a minimal exact-string edit made after a fresh re-read, never a whole-file rewrite.

**Source-of-truth note**: edit `lib/skills/` and the repo, never `~/.claude/skills/`. Do **not** touch installed `~/.claude/skills/decision-*` copies and do **not** run `install-global.sh` — TASK-0122 (the installer prune) removes stale installed skills.

**Design decisions made at task-creation time (autonomous; do not re-litigate)**:

1. **ID resolution keeps DEC- working.** In `lib/skills/_shared/ID-RESOLUTION.md` the `decisions` family row gains `ADR` as the **current** prefix and `DEC` as a **legacy** prefix (pre-migration files). Masks for the family are tried per width in this order: `ADR-<pad4>-*`, `DEC-<pad4>-*`, `ADR-<pad3>-*`, `DEC-<pad3>-*` — the number, not the input's prefix, selects the file, so `DEC-0001#D2` still resolves to `DEC-0001-…md` now and to `ADR-0001-…md` (alias `DEC-0001`) after migration, with no further change to the doc. The `#DM` suffix mechanics are unchanged. Add a worked example for a new `ADR-NNNN#DM` input and keep the existing `DEC-0001#D2` example (it must stay true — verify it against the real filename at implementation time). Do the analogous, minimal table edit for the other families' prefixes only if TASK-0116 has not already restructured the table to support legacy prefixes; reuse whatever mechanism TASK-0116 introduced rather than inventing a second one.
2. **Number allocation is one sequence across both prefixes.** `adr-create` allocates the next number as `max(N)+1` over **both** `ADR-NNNN-*` and `DEC-NNNN-*` (and legacy 3-digit) filenames in `wiki/work/decisions/` (same active/archive scan scope the skill uses today), so a new `ADR-0002` can never collide with `DEC-0001` → `ADR-0001` after migration, and migration never needs to renumber. Record this as the decisions row's parameter in `lib/skills/_shared/SKILL-BOILERPLATE.md` § Number allocation (prefix `ADR-`, also count legacy `DEC-`), and correct the row's note that says filenames are `DEC-NNNN-slug.md`.
3. **Skills read both forms, write only ADR.** Every place a skill *parses* a decision reference or status accepts both prefixes (`--decision ADR-NNNN#DM` or legacy `DEC-NNNN#DM` in `task-create`; `superseded by ADR-N#DX` and legacy `superseded by DEC-N#DX` status text; `wiki-lint` 2.11 target resolution; `roadmap-assess` decision-reference scan; `uat-skip` / `UAT-CORE.md` decision-annotation step). Every place a skill *writes* or *prints* an ID uses `ADR-`. Existing `DEC-0001` prose in historical records and its own file stays exactly as is.
4. **Frontmatter for new items**: `id: ADR-NNNN`, `aliases: [ADR-NNNN]`, H1 `# ADR-NNNN: <Decision-Group Title>`, index entry `- [ADR-NNNN — Title](ADR-NNNN-slug.md) — …`, log line `## [YYYY-MM-DD] adr-create | ADR-NNNN <Title>` (and `adr-accepted` / `adr-superseded` for finalize). `linked_decisions` (roadmaps/requirements frontmatter) is **not** renamed here — the migration task renames it to `linked_adrs`; only its documented value wording changes to "`ADR-NNNN` (legacy `DEC-NNNN`) back-links".
5. **Not in scope**: renaming any existing `DEC-` file/ID/link (migration task), the `linked_*` field rename, removing `archive/` from decisions (separate task), `adr-deprecate`/`adr-assess` (separate tasks), the `req-extract-decisions` → `adr-extract` rename (TASK-0118), the installer prune (TASK-0122). Do not change any skill's behavior, steps, model, or output shape beyond names and ID forms.
