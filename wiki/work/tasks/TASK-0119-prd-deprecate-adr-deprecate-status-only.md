# TASK-0119 — Rename req-retire to prd-deprecate and add a new status-only adr-deprecate

relates_to::[[wiki-skill-boilerplate-duplication]]

## Objective

Hard-rename the `req-retire` skill to `prd-deprecate` and add a new sibling `adr-deprecate`, so the `requirements` (PRD) and `decisions` (ADR) families each get a terminal-action skill under the common vocabulary of ROADMAP-0014 Phase 4. Both skills are **status-only**: they flip a `status:` value, record the reason, move the family-index row into the index's **Closed** section, append a `wiki/log.md` entry, and **never move the file** (no `archive/`, no `git mv`). This deliberately drops the `git mv` archive step (old Step 5.5) that `req-retire` performed. Roadmap item: ROADMAP-0014 Phase 4 ("Rename `req-retire` → `prd-deprecate` and add a new `adr-deprecate`"); binding decisions are items 1-8 of the roadmap Notes (Q&A 2026-09-19), especially #4 (hard rename, no redirect stubs), #5 (no `archive/` for requirements/decisions/roadmaps) and #6 (deprecate skills are kept but status-only).

## Approach

**Sequencing.** Runs after TASK-0118 (the last of the PRD/ADR family renames and `adr-extract`, so the skills are already named `prd-*`/`adr-*` and `lib/skills/req-retire/` is the only `req-*` skill left in the requirements family) and before TASK-0120 (`prd-assess`/`adr-assess`/`uat-assess`). TASK-0121 (archive removal for roadmaps/decisions/requirements) and TASK-0122 (installer prune of stale `~/.claude/skills/` copies, including `req-retire`) come later. Concurrent tasks touch the same shared files, so every edit is a minimal exact-string edit after a fresh re-read — never a whole-file rewrite.

**Source-of-truth note.** Edit `lib/skills/`, never `~/.claude/skills/`. Do **not** touch the installed `~/.claude/skills/req-retire/` copy and do **not** run `install-global.sh` (TASK-0122 prunes stale installed skills).

**Names at implementation time.** Steps below use the post-TASK-0116/0117/0118 names (`prd-create`, `prd-finalize`, `adr-create`, `adr-finalize`, `adr-walkthrough`). If any earlier task left an old name (`req-*`, `decision-*`) in a file this task edits, fix that occurrence too and note it in the final report. IDs: new items are `PRD-`/`ADR-` prefixed; existing `REQ-`/`DEC-` items resolve through `aliases:` until the migration task (TASK-0124), so the skills say `PRD-NNNN` in prose and log entries but must resolve either prefix (ID-RESOLUTION handles this via the family table — see Step 3).

**Design decisions (made autonomously, recorded here):**

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **PRD status value stays `retired`.** `prd-deprecate` flips `status: <draft\|approved>` → `retired` (the lifecycle enum `draft \| approved \| retired` is unchanged). Skill verb is "deprecate"; the terminal status keeps its established name | Lead's instruction; avoids touching every requirement file, the dashboard colour map, `wiki-archive`'s terminal list and lifecycle schema. Documented once in the skill and lifecycle to prevent confusion |
| 2 | **ADR terminal status value is `deprecated`.** Added to both `decisions/lifecycle.md` copies as a third terminal state beside `superseded`: `proposed → accepted → superseded` and `proposed\|accepted → deprecated`. `superseded` stays exclusively owned by `adr-finalize` (it needs a successor block and the atomic two-block update) | `deprecated` is **already used** by `decision-create` (status template `proposed \| accepted \| deprecated \| superseded by …`), `decision-finalize`, `decision-next`, `decision-walkthrough` and `wiki-lint` but was never added to the lifecycle enum — this resolves that drift rather than inventing a new word |
| 3 | **`adr-deprecate` is per-decision (`<file>#DM`).** A Decision Group has no group-level status; each `## DM.` block carries `Status:`. Accepts `proposed` (abandon a draft decision) or `accepted` (withdraw a decision with no successor) → `deprecated`; refuses `deprecated` and `superseded by …` (already terminal) | Mirrors `prd-deprecate` accepting both `draft` and `approved`. Accepted blocks are immutable except a status change — `adr-create` rule 6 currently names only accepted→superseded, so it is widened to include →deprecated |
| 4 | **Index handling (Active / Closed).** After the flip: **requirements** — the row moves from Active to **Closed** (`retired`). **decisions** — the group row stays in Active while any block is still `proposed`; when none remain it lives in Closed, and its trailing per-block status summary (`D1 proposed, D2 accepted, …`) is updated to show `deprecated`. The **Closed** section is created (`## Closed` heading, same entry format) if the index does not have one yet, so the skills work whether or not TASK-0121 has landed; TASK-0121 owns the final index wording — **re-read TASK-0121 (if on disk) and `wiki/work/{requirements,decisions}/index.md` first and use its exact section headings** | Coordinates with TASK-0121 without depending on it; the rows never leave the family directory |
| 5 | **No `git mv`, no `Bash` at all.** The skills are pure `Read`→`Edit`. `req-retire` CRITICAL rules #1 and #5 ("archiving is the terminal action", "`Bash` only for `git mv`") are dropped, replaced by "never move the file; `archive/` is not used" | Roadmap Notes #5/#6 |
| 6 | **Shared docs, not restatement.** ID resolution via `_shared/ID-RESOLUTION.md` (scope `active`; an item still sitting in a legacy `archive/` resolves to STOP-not-found until TASK-0124 un-archives — say so in the skill), Edit hygiene via `_shared/SKILL-BOILERPLATE.md § Edit hygiene`. `_shared/ARCHIVE-WORK-ITEM.md` does **not** apply (it covers only families that still archive) — remove `req-retire` from its "Other consumers (not yet wired)" note. Number allocation is not needed (no new item) | Lead's instruction |
| 7 | **Log entry types**: `## [YYYY-MM-DD] prd-deprecated | PRD-NNNN <title> — reason: …` and `## [YYYY-MM-DD] adr-deprecated | ADR-NNNN#DM <title> — reason: …` (was `req-retired`); historical `req-retired` lines in `wiki/log*.md` are never edited | Log is append-only |
| 8 | Both skills keep `req-retire`'s frontmatter shape: `category: planning`, `model: claude-haiku-4-5-20251001` (mechanical/bookkeeping), `user-invocable: true`, and the same downstream-artifact surfacing (**never auto-cascade**; suggest `/task-close`, `/adr-create deprecate …` etc.) | Behavior otherwise unchanged; only the archive mechanics change |
