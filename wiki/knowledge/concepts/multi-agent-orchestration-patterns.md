The decision to go from a single augmented LLM to a multi-agent system is a cost/complexity tradeoff, not a maturity milestone. Anthropic's own research system (lead agent + parallel subagents) beat a single agent by 90.2% on a breadth-first research eval, but multi-agent systems run at roughly 15x the token cost of a single chat interaction (agents alone run ~4x). The pattern earns its cost specifically for **breadth-first, parallelizable** work — independent facets of a query, independent files/records — not for tasks with one linear reasoning chain, where it only adds latency and failure surface. Anthropic's own guidance, and independent 2026 production data (40% of multi-agent pilots failing within six months), both warn that teams routinely over-build multi-agent systems that a better-prompted single agent would have matched.

Among named coordination topologies (orchestrator-worker/hub-and-spoke, supervisor/router, pipeline/sequential, swarm/mesh), **hierarchical orchestrator + isolated subagents is the pattern that has actually survived 2026 production deployments**. Peer-to-peer "group chat" coordination failed in production: cascade-failure research found a single false premise can propagate to 100% of agents in hub-and-spoke topologies under fault injection, and peer topologies fare worse. Anthropic's 8 prompt-engineering principles for lead agents are directly reusable for any orchestrator design: give every subagent an explicit objective, output format, tool/source guidance, and task boundary; embed effort-scaling rules so a simple query doesn't spawn dozens of subagents; have subagents return a distilled summary (not their full transcript) to the lead, since raw transcripts pollute context and burn tokens at the 15x rate.

**Compounding error is the core engineering risk** of any multi-step or multi-agent chain, independent of which topology is chosen: at 85% per-step accuracy (considered good), a 10-step chain succeeds only 19.7% of the time (0.85^10). In multi-agent systems specifically, a wrong or stale output from one agent poisons every downstream agent's context, and lossy summarization compounds the problem further. The documented architectural fix is decomposing into small, independently-verifiable atomic subtasks (a DAG of checkable units) rather than a monolithic chain — not better prompting alone. Anthropic's alignment research adds a subtler caution: individually-benign behavioral quirks in each agent can compound into unwanted *global* outcomes across a multi-agent system, so per-agent safety does not automatically compose into system-level safety.

`implements::[[Power Mode Skill]]` and `implements::[[Now Skill]]` in this repository are both hierarchical orchestrator-worker implementations, consistent with the pattern that survived production per this research — `power-mode` mandates a minimum team of 5 collision-safe parallel workers per wave with mandatory per-agent task-boundary instructions (matching Anthropic's delegation principles above); `now` is the lighter-weight version (max 3 concurrent). Neither repo skill uses a peer/group-chat topology, which this research flags as the documented production failure mode.
